# 文字UNO房间

Yukino 原创文字实现，MIT。没有上游游戏代码、牌面、美术、音效或第三方资源；不联网、不调用模型、不下注、不主动私聊或推送消息。所有操作均由玩家发送指令触发。

## 从建桌到出牌

1. 在同一QQ群发送 `/UNO 创建`，获得随机六位房间码。其他玩家发送 `/UNO 加入`。一群同时一桌，2—6人。
2. 创建者或配置中的机器人主人发送 `/UNO 开始`。每人7张，创建者先手，座位依次按加入顺序排列。
3. **每位玩家主动私聊机器人**发送 `/UNO 手牌 ABC234`，把示例码换为本桌房间码。只有真实QQ用户本人是成员才能读到自己的牌；机器人主人也不能读取别人的牌。群内任何手牌命令都会拒绝。
4. 回原群发送 `/UNO 出 3`，表示打出当前手牌编号3。打出万能或+4时必须写颜色，例如 `/UNO 出 3 蓝`。每次出牌后编号可能移动，请再私聊查看。
5. 或发送 `/UNO 摸牌`，只摸1张；当回合可以打出**刚摸的这一张**，或 `/UNO 跳过`。不能连续摸牌，也不能没摸牌就直接跳过。摸牌消息不会在群里透露牌面。
6. 出牌后剩1张时，赶在下一次有效出牌、摸牌或跳过之前发送 `/UNO 喊UNO`。漏喊会在下一次有效回合行动前补抽2张；无效指令、看状态、看手牌不会消耗喊UNO窗口。

`/UNO 状态` 只展示座位、每人牌数、顶牌、当前颜色、轮次及方向。`/UNO 结束` 仅创建者或机器人主人可用。`/UNO 帮助` 随时查看用法。小写 `/uno` 同样可用。

加入、开始、状态和结束可在后面附上本群房间码；房间码不允许用来跨群操控其他桌。私聊只能查看自己的手牌，不能创建空桌、出牌或代操作。已开始后不能加入或替换座位。

## 固定规则

- 共108张：红黄绿蓝每色25张（0一张，1—9及跳过、反转、+2各两张），万能4张，+4四张。
- 匹配当前颜色或顶牌数字/符号即可出；万能自由选择颜色。+4仅在自己手中**没有当前颜色的有色牌**时可用，不做质疑流程。
- 跳过使下一位跳过；反转改变方向，两人时反转相当于跳过，让出牌者再行动。
- +2/+4立刻罚下一位抽2/4张并跳过；**不叠罚、不允许靠另一个+2或+4抵消罚抽**。之后轮到其他玩家时仍可正常匹配符号出牌。
- 开局的公开顶牌固定选有色数字牌，避免开局动作牌争议；其他牌留在抽牌堆。
- 抽牌堆用尽时，只重洗顶牌之外的弃牌；顶牌和当前颜色保留。不创造新牌。若抽牌堆、可回收弃牌都不足，只抽剩余数量并明确提示；手牌中的牌不会被回收。
- 最后一张是动作牌时，先完成反转、跳过或罚抽，再判定手牌出完的玩家获胜。
- 每局最多1000次出牌/跳过（可配置）；达到上限按手牌数量最少结算，并列同胜。单独摸牌不额外消耗回合；每回合最多摸一次。
- 没有组合出牌、抢出、交换手牌、万能自定义、额外+4质疑或筹码规则。

## 面板参数

| 参数 | 默认及范围 | 生效时机 |
| --- | --- | --- |
| `max_players` | 6，范围2—6 | 创建新桌时固定座位上限 |
| `max_rooms` | 200，范围10—1000 | 新建桌时限制总记录数；优先清理最早结束桌，不挤掉进行中的桌 |
| `expiry_days` | 31，范围1—31 | 每次指令清理最后游戏操作后过期房间 |
| `hand_page_size` | 30，范围10—60 | 私聊即时分页；`/UNO 手牌 房间码 2` 看第2页 |
| `max_moves` | 1000，范围50—5000 | 开始新局时固定回合上限 |

## 持久化和隐私边界

固定使用宿主分配的 `data_dir/uno.sqlite3`，聊天内容不能指定路径。房间码、玩家QQ标识、所有牌堆与回合在数据库里持久化；worker回收、内核重启后可继续。更新使用SQLite事务，非法操作不提交，重复同时加入不会占两个座位。

公开状态和普通操作回执不包含任何人的手牌或抽牌堆。私聊只向真实 `context.user_id` 对应成员返回其本人手牌；知道房间码不等于获得成员权限。看状态和看手牌不延长房间寿命，游戏操作才更新时间。插件不提供自动发送他人手牌的接口。

输入最多200字符；单人最多108张、单页最多60张；房间最多6人。源包只含代码与说明，不含运行数据库、凭据或QQ群信息。管理员有本机文件权限时仍能读取数据库，应按普通机器人私密数据保管。


## 模型参与（Core 0.10.0）

本插件声明原生游戏AI适配器。创建/开始加“人机”或发送 `/UNO 加入AI`，之后由内核按回合自动调用当前会话模型。插件管理可开启“开新局时自动邀请AI”；AI退出、AI状态、AI重试可用于本局管理。单人题目采用搭档方式，每次真人动作后最多协作一步。完整规则及隐藏信息边界见[AI游戏指南](https://github.com/Le672/yukino-core/blob/main/docs/GAME_AI.md)。本地规则引擎本身不联网；模型调用由内核管理。
