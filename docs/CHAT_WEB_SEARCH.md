# 普通聊天联网查询

0.9.0 增加独立于指令插件的可选检索步骤。启用后，正常问「Python 现在最新的稳定版本是什么」「上海明天天气怎么样」就能触发，不需要斜杠指令。QQ 的消息接收、群白名单和聊天触发方式仍由「对话策略」控制。

## 启用与数据范围

新安装默认关闭。管理员应先取得使用者同意，再打开「对话策略 → 聊天联网查询 → 启用聊天联网查询」。搜索服务会收到从问题提炼的关键词；开启追问时，可能包含同一会话同一人的上一条问题。不会把 QQ 元数据、昵称、整段聊天记录、长期记忆或模型配置交给搜索服务。

不要在查询中输入私密资料。内置规则跳过常见凭据、邮箱、长账号数字和本地路径，但这些规则不能识别所有隐私。群使用者应知道已启用联网查询；需要更严格控制时，关闭自动识别，只在明确说「查一下」「搜索」时查询，或使用自己的搜索服务。

默认先使用 DuckDuckGo 的公开 HTML 搜索，失败时尝试 Bing RSS；它们并非带可用性保证的 API，可能限流、要求验证或返回过旧/无关结果。可选配置支持 JSON 的 SearXNG，例如 `https://search.example.com/search`。SearXNG 自建方式与 `format=json` 见[上游搜索 API 文档](https://docs.searxng.org/dev/search_api.html)。无须为默认入口提供 API Key。

## 回复流程

1. 闲聊、人设问题等跳过独立检索；明确搜索或外部事实/时效问题按规则选择。
2. 查询及有限的正文读取共享总耗时预算；只访问公开 HTTPS 地址。
3. 将带来源 URL、检索时间的资料交给当前会话选定的模型，一次生成答案。
4. 按既有人格自然回答；对比和步骤按需求展开，资料不足时说明，而不是编造实时结论。

模型有原生搜索工具时仍可能自行检索。核心不会给不支持工具的模型凭空增加原生工具。独立检索把公开参考文本接到全部现有模型通道；它也不等于向模型提供整页图片或完整视频。

## 可调设置

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| 启用聊天联网查询 | 关闭 | 独立搜索的总开关 |
| 自动识别需要查询的问题 | 开启 | 关闭后只检索明确要求搜索的消息 |
| 追问参考同一人上一条问题 | 开启 | 不跨会话、不使用其他群成员的问题 |
| 检索总耗时 | 10 秒 | 搜索、回退和正文读取共用 |
| 搜索结果数 | 5 | 最多 8 个 |
| 正文读取数 | 2 | 0 到 3 页 |
| 每页正文字符 | 2400 | 截断较长页面，避免塞入大量无关内容 |
| 缓存时间 | 180 秒 | 0 为关闭，最多 128 项，仅存内存 |
| SearXNG 地址 | 空 | 留空使用内置入口 |

缓存不会更新原检索时间；失败仅短暂缓存，避免反复等待。重启清空缓存。不会把搜索词或页面写入状态日志，但 QQ 问答本身仍依照核心原有的历史保存功能处理。

## 验证与限制

在控制台「隔离测试」输入公开测试问题，可以核对模型回复、来源数量、缓存状态和总耗时；该页面不发 QQ。`/api/status` 的 `web_search` 提供请求/成功/失败/缓存命中数，不含原始查询内容。

结果里只有 `snippet` 的项是搜索摘要；有 `content` 和 `read_at` 的项才表示正文读取成功。检索时间不是文章发布日期。付费墙、登录页面、验证码、非 HTML、过大响应或拒绝连接的页面不会绕过限制，正文失败时仍可能只提供摘要。模型需要判断相关性与时效；搜索成功不代表答案必然正确。

聊天检索通常增加少量等待，达到上限便停止。模型调用耗时另外计算；没有追加一次“润色模型”来拖慢每轮对话。人格可继续在「人格与设置」编辑。
