# 小游戏里的模型玩家

Core 0.10.0 与对应1.3.0游戏插件支持41项玩法。18项采用玩家席位或对战方式，23项单人题目采用搭档方式。动作由会话选定的模型产生，原有本地规则仍负责合法性、计分和胜负；没有更换模型服务，也没有让模型执行任意指令。

## 开始玩

- `/谁是卧底 创建 人机`：主持人和AI先入席，另一名真人发送 `/谁是卧底 加入`，再由主持人 `/谁是卧底 开始`。至少两名真人和一名AI。
- `/UNO 创建 人机`，然后 `/UNO 开始`：一名真人即可与AI对战。玩家仍需私聊 `/UNO 手牌 房间码` 查看自己的牌。
- `/五子棋 开始 人机`：你先落子，之后AI按回合自动落子。
- `/扫雷 开始 人机`：AI作为同一题目的搭档，每次真人动作后协作一步，不会一次跑完整局。
- `/猜拳 开始 人机`：等AI先公布出拳承诺，再出石头、剪刀或布。它会揭示承诺原文以供核对，再准备下一轮。

已经创建、尚有座位的房间可以发送同一游戏前缀加 `加入AI`。开始/创建加 `纯玩家` 可只玩真人局，例如 `/谁是卧底 创建 纯玩家`。新的公开安装默认不会自动往真人局塞入AI；“插件管理 → 对应游戏 → 开新局时自动邀请AI”可改变这一点。

加入以后不需要每一步都输入“让AI行动”。描述、投票、出牌、落子等在轮到它时自动进行。正常的真人操作仍遵循各游戏指令；卧底模式在轮到本人描述时，可以直接正常发一条群消息，无需@或前缀。AI模式的卧底局先完成本轮所有描述，再投票；齐票自动结算，平票进入下一轮描述。

## 本局管理

各游戏前缀后均可使用：

| 操作 | 作用 |
| --- | --- |
| 加入AI | 由发起者或机器人主人邀请；重复邀请不增加回合 |
| AI状态 | 查看当前是否参加，并恢复检查待执行回合 |
| AI重试 | 模型恢复后重新检查待执行回合；通常下一条玩家消息也会触发检查 |
| AI退出 | 单人题目只停止搭档；多人房间在等待阶段移除AI，进行中则结束本局，避免留下无主座位 |

房间人数上限仍有效。AI只占一个席位，不会替代其他真人或自动生成多个虚拟玩家。海龟汤保留真人主持人，AI是提问玩家；你说我猜保留真人给线索，AI是猜题玩家；抢答正误仍由真人主持判定。

## 设置与耗时

“对话策略 → 小游戏里的AI玩家”提供总开关、每次思考超时、游戏每小时模型调用总上限。每个游戏在插件管理中有独立AI开关、自动加入和连续动作上限。默认每小时最多120次模型请求，每次最多100秒，逐游戏默认连续3步。

同一轮只有一个合法动作时直接执行规则，不花模型请求。UNO摸牌、额外回合、点格棋连走等需要继续操作时会自动接续，并让出处理机会；没有用无限循环占满模型。到达小时限额、模型不可用或输出持续不合法时停止自动尝试，保留存档，下一条玩家消息可继续检查。

模型玩家与普通聊天共用当前模型服务，可能需要等待。切换会话模型同样影响后续游戏动作。单人搭档每次真人动作后只走一步，避免消耗整局和大量额度。

## 信息与规则边界

- 谁是卧底：只提供AI自己的词、存活玩家和本轮公开描述；不提供真实卧底身份、其他玩家的词或完整发牌表。发言会检查原词泄露。
- UNO：只提供自己的手牌、公开顶牌、颜色、玩家手牌数量和合法行动；不提供别人的手牌或抽牌顺序。剩一张时自动喊UNO。
- 扫雷、海战、翻牌、猜词等：只看公开画面和已公开结果；不提供未揭开的雷、舰船、牌面或标准答案。
- 数独、数织、24点、麻将训练：题面可见，内部解答字段不进入模型上下文。模型可能答错，仍按原规则消耗次数或计分。
- 模型输出只能是合法编号或本游戏需要的短发言/答案。它不能借游戏输出踢人、文件路径、其他插件命令或管理操作。
- 每次提交都检查原局面是否仍有效；真人在思考期间改变了局面，旧动作会作废并重新检查。游戏上下文与普通聊天记忆分开，不联网查答案。
- 关闭接收、停用插件、重置会话或QQ禁言时不继续自动发言。重启保留参与记录，但不会在启动时回放旧动作。

“AI支持”表示这个内核适配了所列原生游戏规则。任意第三方同名插件、麦麦/AstrBot插件或不同数据库格式不会因此自动兼容。

## 维护与开发

游戏插件1.3.0声明 `game_ai_adapter: 1`，要求Core0.10.0；其本地规则文件仍独立运行，模型调用集中在内核。核心按固定适配器生成可见信息与动作集合，插件进程负责按原规则提交，未声明适配器的普通插件保持原行为。

修改或重新生成目录后，执行 `python scripts/sync_game_ai_catalog.py`，同步游戏清单、元信息与说明，再运行核心及对应扩展测试。新增游戏不能仅伪造这个字段：需要实现对应公开视图、动作校验与隔离测试。控制台 `/api/status` 的 `game_ai` 只包含房间数量、调用和错误计数，不包含手牌、词语或原始模型响应。
